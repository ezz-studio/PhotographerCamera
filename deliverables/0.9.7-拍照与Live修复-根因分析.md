# 0.9.7 修复报告：JPEG MAX / RAW MAX / Live 无法拍照

对照 upstream（`photon-camera/`，`com.hinnka.mycamera`）逐文件 diff + 真机远程日志（`_diag/s*.txt`）取证后得出以下结论。

---

## 1. Upstream 状态机（单一事实源链）

```
prefs.useRaw ──┬─> effectiveUseRaw    = useRaw && !multipleExposure
prefs.useJpgMax ─> effectiveUseJpgMax = useJpgMax && !effectiveUseRaw && !multipleExposure
prefs.useRawMax ─> effectiveUseRawMax = useRawMax && effectiveUseRaw && !multipleExposure
                │  （更新路径里 desiredUseRawMax = desiredUseRaw，RAW Max 恒等于 RAW）
                ▼
multiFrameOutputScale = when { useRawMax -> normalize(rawMaxOutputScale)
                               useJpgMax -> 1f
                               else -> null }          ← 关键：null = 不进多帧管线
                ▼
CameraState（CameraState.kt:411-433）:
  isMultiFrameEnabled = multiFrameOutputScale != null && (!useRaw || isRawSupported)
  isJpgMaxEnabled     = isMultiFrameEnabled && !useRaw
  isRawMaxEnabled     = isMultiFrameEnabled && useRaw
  requiresMultiFrameCaptureSequence = isMultiFrameEnabled && activeMultiFrameCount > 1
```

**切换模式除 boolean 外还触发**（CameraViewModel.kt:840-880 / 2013-2110）：
- `resolveMultiFrameOutputScale` 变化 → `needsCameraReopen` → **重开相机**（ImageReader 格式/尺寸是会话级选择）
- `setUseRaw` → Controller 里 `restartCameraForCaptureOutputMismatch` 重建会话
- `setUseLivePhoto(enabled)`（Controller:8609）→ **启动/停止 LivePhotoRecorder**（录制器生命周期随模式切换）
- `setJpgMultiFrameDenoiseFrameCount / setHdrPlusFrameCount / setUseJpgMaxHdrComposition` → 决定 reader 深度与请求帧数
- Live 开启时 `activeUseJpgMax` → `saveUseLivePhoto(false)` 持久化互斥

## 2. 模式互斥关系（upstream 三条，全部成立）

| 互斥 | upstream 实现位置 |
|---|---|
| JPEG Max ⊥ RAW Max | `activeUseJpgMax = useJpgMax && !useRaw`（同一 `useRaw` 开关派生，结构性互斥） |
| Live ⊥ JPEG Max | `setUseLivePhoto(live && !effectiveUseRaw && !effectiveUseJpgMax && PHOTO)` + `saveUseLivePhoto(false)` |
| Live ⊥ RAW Max | 同上（`!effectiveUseRaw` 分支） |

当前项目 `resolveJpgMaxActive(useRaw, useLivePhoto) = !useRaw && !useLivePhoto` **三条互斥规则全部满足**——互斥逻辑本身不是 bug。

## 3. 当前项目状态（与 upstream 的唯一实质差异）

- upstream：`useJpgMax` 默认 **false** → 默认单帧拍摄，不进多帧管线
- 当前项目：`resolveJpgMaxActive` 把 JPEG MAX **固定为开启**（RAW 关 & Live 关时恒 true）→ **每次快门都走多帧 burst 路径**
- RAW MAX 同理：`prefs.useRawMax = requestedUseRawMax || storedUseRaw`，RAW 开即恒 true

## 4. Profile 参与点（已逐包核实，无冲突）

| 链路 | 是否涉及 Profile |
|---|---|
| `photon/camera/`（Camera2 / CaptureRequest / ImageReader 格式） | **否**（grep 0 命中） |
| `photon/viewmodel/`（拍摄前状态机） | **否** |
| `ui/screens/CameraScreen.kt:369-410` | 是：Profile → `ProfileToRecipeMapper` → `ColorRecipeParams` + `LensParamsStore` / `FilmParamsStore` 单例 |
| 消费方 `LutRenderer`（预览）/ `LutImageProcessor`（成片）/ `RawDemosaicProcessor.profileToneMapMode`（RAW 显影） | 是，全部在**图像交付之后**的处理阶段 |

**结论：Profile 只参与"成片后处理"，不参与拍摄前的 Camera2 / CaptureRequest / RAW / JPEG / Live 管线配置，与模式互斥无冲突。**

## 5. Root Cause（真机日志取证）

### BUG-1：JPEG MAX / RAW MAX 都拍不出照片
```
16:43:31.651 [SHOT] capture setup FAILED: java.lang.SecurityException:
  To use the sampling rate of 0 microseconds, app needs to declare the normal
  permission HIGH_SAMPLING_RATE_SENSORS.   ← readerFormat=YCBCR_P010（JPEG MAX）
16:43:37.449 同样异常                        ← readerFormat=RAW_SENSOR（RAW MAX）
```
- 端口漏掉了 upstream 已声明的 `android.permission.HIGH_SAMPLING_RATE_SENSORS`（upstream Manifest:17）
- 且 0.9.6 把 `burstGyroRecorder.start()` 挪到了 `try` **之外**（upstream:7121-7126 在 `try` 内）
- 因为 JPEG MAX 被固定开启，**所有**快门都进多帧路径 → 都撞上这个异常 → 全部拍不出

### BUG-2：Live 拍摄卡死
```
13:28:09.119 Camera error: 0, error=4 - 相机设备遇到严重错误   ← 成片永远不会交付
00:44:17~16:57:44 "Stop requested while capture in progress, delaying encoder release" ×20+
```
- 成片未交付时 `LivePhotoRecorder.isCapturing` 永久 true
- 之后每次 `stopRecording()` 只把 release 挂起（`pendingRelease=true`），编码器永不释放 → 录制器永久卡死

## 6. 最小修复（已实施，7 文件 +218/-34）

**BUG-1**
1. `AndroidManifest.xml` 补 `HIGH_SAMPLING_RATE_SENSORS`（对齐 upstream，normal 权限装即授）——**根因修复**
2. `BurstGyroRecorder` / `RealtimeStabilizationCoordinator`：采样周期从快到慢降级兜底（首选仍是 FASTEST，行为同 upstream）
3. `capture()`：gyro start 收进 try（对齐 upstream:7121），异常不再中断拍摄

**BUG-2**
4. `LivePhotoRecorder`：10s 拍摄看门狗 + `cancelPendingCapture()` + 停止时若已停滞则强制复位（不再无限挂起 release）
5. `Camera2Controller`：相机 error / 拍摄失败 / 拍摄异常时放弃挂起的 Live 拍摄
6. `setUseP010` 改动会话级失配检测（P010 与 RAW 一样是 ImageReader/会话级选择，只写 state 不生效）——对齐 upstream 对 RAW 的处理方式

**回退的两处推测性改动**（review 后发现实际风险）：
- ~~`resolveImageReaderMaxImages` 内存封顶 + Live 降深~~：`checkBurstCaptureContinue` 要求空闲帧位 ≥ 8，封顶到 4/3 会让连拍永久等待（CameraViewModel:3108 已接线 startBurstCapture）；且实测 error 4 发生在 reader=7（多帧路径，本就不受封顶影响）→ 回退
- ~~`handleMultiFrameSequenceFinished` 的 `isMultiFrameEnabled` 守卫~~：回调本就只在 `requiresMultiFrameCaptureSequence` 时触发，守卫多余且可能跳过必要的收敛复位 → 回退
